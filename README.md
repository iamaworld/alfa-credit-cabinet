# Умный кредитный кабинет предпринимателя

Прототип для кейса «Умный кредитный кабинет предпринимателя» (хакатон «Альфа-Будущее»). Клиент малого бизнеса вводит ИНН, видит предодобренный лимит с причинами, двигает сумму и срок и сразу видит, что и почему меняется, подаёт заявку и следит за ней в кабинете. На стороне банка — конвейер проверки, скоринг, решение и кабинет аналитика. Все данные синтетические, внешние сервисы заменены моками.

Интерфейс сделан по открытой дизайн-системе Альфа-Банка (core-ds/core-components): палитра, кнопки, поля, иконки из `@alfalab/icons-glyph`. Логотип банка из `@alfalab/icons-logotype` используется с разрешения для прототипа хакатона; фирменный шрифт Styrene заменён на свободный Onest.

## Быстрый старт

```bash
docker compose up --build
# откройте http://localhost:3000
```

Поднимаются приложение, три мока (ЕГРЮЛ/ЕГРИП с «Прозрачным бизнесом», бюро кредитных историй, выписка по счёту) и локальная языковая модель для ИИ-помощника. Порт, секрет и параметры модели настраиваются через `.env` (пример в `.env.example`).

Первый запуск дольше: один раз скачиваются образ llama.cpp (~310 МБ) и модель Qwen3-1.7B (1,8 ГБ, с проверкой SHA-256). Модели нужно около 2,5 ГБ памяти Docker. Кабинет открывается сразу, не дожидаясь модели: пока она загружается, помощник разбирает текст по правилам. Выключить ИИ полностью: `LLM_ENABLED=0`.

Без Docker (нужен Node.js 22.13 или новее):

```bash
cd app && npm ci && npm run dev    # моки и приложение в одном процессе
# откройте http://localhost:3000
```

Тесты: `cd app && npm test`.

### Облачная демо-версия

Для показа без установки — один контейнер `Dockerfile.cloud`: приложение и три мока в одном процессе, ~40 МБ памяти, подходит для бесплатных тарифов. Языковая модель в облачной версии не запускается (ей нужно ~2,5 ГБ памяти): ИИ-помощник работает в запасном режиме по правилам, всё остальное — как в полной версии. База живёт внутри контейнера и сбрасывается при перезапуске.

Развёртывание на Render: Dashboard → New → Blueprint → выбрать этот репозиторий (`render.yaml` уже настроен). Бесплатный сервис засыпает без запросов: первое открытие после простоя — до минуты.

## Демо за три минуты

1. Войдите как `client-a`. Наверху — денежный календарь: в апреле остаток уходит в минус. Нажмите «Закрыть разрыв» — овердрафт подобран, и график показывает, что разрыв закрыт. Ниже — блок «На что нужны деньги?»: опишите задачу своими словами, локальная модель подберёт продукт, сумму и срок.
2. Нажмите «Настроить условия», сдвиньте срок: появится «Что изменилось и почему».
3. Оформите заявку, приложите документы, отправьте. Статусы идут сами, итог — «Одобрено». Примите условия и подпишите.
4. Подайте заявку на 5 000 000 ₽ и войдите как `analyst`: заявка в очереди. В карточке — справка: вывод, на что смотреть (в том числе стресс-тест «выручка −20 %») и вопросы клиенту; кнопка «Задать вопрос» переносит вопрос в «Запросить данные». Одобрите с комментарием.
5. Войдите как `client-b`: «Другие условия» с тремя вариантами. Как `client-d`: отказ с причинами и планом.

Все сценарии с ожидаемыми результатами: [docs/TEST_SCENARIOS.md](docs/TEST_SCENARIOS.md).

## Денежный календарь и лента под клиента

Главный экран клиента — прогноз денег на счёте на 12 месяцев по выписке. Предприниматель заранее видит месяцы, когда денег может не хватить, и закрывает разрыв в один клик; в редакторе условий видно, как выбранный кредит ляжет на остаток по месяцам.

- **Прогноз** (`app/src/engine/cashflow.js`) повторяет то, что повторяется: зарплату, аренду, долю поставщиков от выручки, налоги по месяцам года и ежегодные события прошлого года (страховка парка, сезонные закупки). Разовые траты прошлого года (покупка тягача) в прогноз не переносятся.
- **Разрыв** — месяц с отрицательным остатком. Календарь предлагает овердрафт с запасом 15 % на срок до конца разрыва и проверяет, что предложение действительно закрывает разрыв.
- **Овердрафт моделируется как лимит:** деньги берутся, только когда остаток уходит в минус, проценты — за использованную сумму, долг гасится поступлениями. Обычный кредит — поступление на счёт и аннуитетные платежи; кредит на оборудование на счёт не приходит (сразу оплата покупки).
- **Лента меняется под клиента**, потому что строится из его прогноза: «В апреле может не хватить денег» у транспортной компании (страховка парка и годовой налог), «Закупка к новогоднему сезону» у ИП-торговца, «Календарь появится после подключения счёта» у клиента без выписки. Клиенту со стоп-фактором (просрочка) кредит в ленте не предлагается — только предупреждение.
- **График** доступен с клавиатуры, у каждого месяца подсказка с поступлениями, списаниями и событиями, есть таблица по месяцам. Цвета серий проверены на различимость при нарушениях цветового зрения.

Сценарии: `client-a` — разрыв в апреле, овердрафт на 300 тыс. ₽ его закрывает; `client-b` — короткие разрывы после сезонных закупок; `client-c` — нет выписки; `client-d` — разрыв при просрочке, без предложения кредита.

## Справка аналитику

В карточке заявки аналитика первым блоком — справка: вывод, «на что смотреть» по серьёзности и вопросы клиенту. Вопрос одной кнопкой переносится в действие «Запросить данные».

- **Факты** (`app/src/services/brief.js`) собираются из данных заявки, у каждого — источник: ЕГРЮЛ, «Прозрачный бизнес», БКИ, выписка, расчёт движка, денежный календарь. Календарь добавляет, как кредит ляжет на остаток, и стресс-сценарий «выручка −20 %».
- **Вывод и вопросы строятся по правилам.** Мы пробовали языковую модель (Qwen3-1.7B) для этого блока: она путала факты «за» и «против», задавала вопросы не клиенту и отвечала 16–40 секунд. Справка, которая иногда ошибается, хуже никакой, поэтому ИИ оставлен там, где он измеримо точен, — в разборе задачи клиента.
- Пример: заявка на 6 млн ₽ у здоровой компании — «Факторов за — 6, против — 2. Главное сомнение: если выручка упадёт на 20 %, остаток с кредитом уйдёт в минус в мае».

## ИИ-помощник: задача своими словами

На главной клиент пишет, на что нужны деньги («клиенты платят через 60 дней, а зарплату 800 тысяч нужно платить сейчас»), и сразу попадает в редактор условий с подобранными целью, продуктом, суммой и сроком. Рядом видно, что он написал и как это поняли.

- **Модель:** Qwen3-1.7B (открытые веса, Apache 2.0) на сервере llama.cpp, только CPU, внутри Docker. Данные никуда не уходят.
- **Что делает модель:** определяет цель и выбирает нужные сумму и срок среди упомянутых в тексте. Ответ строго по JSON-схеме (грамматика на стороне сервера).
- **Не задача — не кредит:** «как дела», «привет», вопрос о погоде помощник не превращает в заявку, а просит описать, на что нужны деньги. Если в тексте нет ни цели, ни суммы, ни денежных слов, ответ мгновенный, без модели; в пограничных случаях («как оплатить парковку у офиса») модель отдельно отвечает, про финансирование ли это (12/12 на проверочном наборе).
- **Не всякая цель — кредит:** цели, которые банк не финансирует (интим-услуги, наркотики, азартные игры, взятки, обнал), личные расходы (еда, отпуск, свадьба) и суммы меньше 10 000 ₽ отсекаются правилами до модели с понятным объяснением. Слова подобраны так, чтобы не задевать обычные бизнес-фразы («купить себе на склад погрузчик», «откатные ворота для цеха»).
- **Чего модель не делает:** не принимает кредитных решений и не придумывает числа. Сумма и срок принимаются, только если такие числа есть в тексте; затем они приводятся к лимитам продукта, а условия считает тот же движок, что и везде.
- **Отказоустойчивость:** если модель не загрузилась, ответила не по схеме или дольше `LLM_TIMEOUT_MS`, работает разбор по правилам; интерфейс пишет, каким способом разобран текст. Модель прогревается при старте и когда клиент открывает главную.
- **Качество** (замер на 20 фразах, половину из которых при настройке не видели): модель — 18/20 верно; правила — 10/10 на фразах, под которые их настраивали, и 4/10 на незнакомых; оба расхождения модели спорные («кофемашина для новой точки» → оборудование). Время ответа на Apple M2 в Docker — 1–4 с, первый запрос после прогрева до ~7 с.
- **Замена модели:** клиент говорит по OpenAI-совместимому API, поэтому вместо llama.cpp подойдут Ollama или vLLM с любой моделью с открытыми весами.

Код: `app/src/services/llm.js` (клиент модели), `app/src/services/intent.js` (разбор и проверки), тесты — `app/test/intent.test.js`.

## Как устроено

- **Один движок** (`app/src/engine`) считает предодобренный лимит, пересчёт в редакторе, оценку заявки и варианты «другие условия». Поэтому цифры не расходятся.
- **Скоринг и решение разделены.** Скоринг оценивает риск, политика решает: одобрить автоматически, отправить человеку, предложить другие условия или отказать.
- **Автомат статусов** (`services/statuses.js`) — единственный источник правды о переходах; журнал событий хранит автора каждого шага.
- **Сбои источников** не ломают заявку: используется последняя сохранённая копия данных, решение уходит аналитику с пометкой.
- **Клиенту не отдаются баллы и пороги.** Он видит факторы и направление влияния.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/DECISION_MODEL.md](docs/DECISION_MODEL.md).

## Допущения и ограничения

- Подпись договора и выдача денег имитируются кнопкой, загрузка документов сохраняет только имя файла.
- Подключение компании по ИНН не проверяет полномочия пользователя. В реальном продукте нужна подпись или доверенный канал.
- Модель решения учебная: пороги и веса выдуманы и не откалиброваны на реальных данных. Доля свободного денежного потока по отраслям — допущение.
- Меры государственной поддержки в ленте — демонстрационные примеры и гипотеза продукта, а не справочник.
- Конвейер работает в процессе приложения. Для продакшна нужна очередь задач, PostgreSQL и реальные адаптеры источников.
- Регистрации нет: доступны только тестовые аккаунты. При `SEED=0` они не создаются.
- Шрифт Onest — свободная замена фирменному шрифту банка.
